## 🔧 如果遇到問題

### 問題 1: 資料庫錯誤
**症狀**: 應用程式啟動時出現資料庫相關錯誤

**解決方案**:
1. 關閉 Electron 應用程式
2. 刪除用戶資料目錄中的資料庫：
   - Windows: `%APPDATA%\spreadsheet-comparator\dev.db`
3. 重新啟動應用程式（會自動創建新資料庫）

### 問題 2: 表單沒有新欄位
**症狀**: 創建任務時只有一個輸入欄位

**可能原因**: 
- 前端代碼沒有正確打包
- 需要重新打包 Electron 應用程式

**解決方案**:
```bash
npm run electron:package
```

### 問題 3: Prisma Client 錯誤
**症狀**: 出現 "Unknown field" 錯誤

**解決方案**:
```bash
# 重新生成 Prisma Client
npx prisma generate

# 重新打包
npm run electron:package
```

## 📝 測試步驟

### 步驟 1: 打包 Electron 應用程式

```bash
# 使用自動化腳本
npm run electron:package

# 或手動執行
.\build-electron.ps1
```

### 步驟 2: 運行打包後的應用程式

```bash
# 執行檔位置
.\dist-electron\win-unpacked\Spreadsheet Comparator.exe
```

### 步驟 3: 測試新功能

1. **測試標題與描述**:
   ```
   1. 點擊「新增提醒」
   2. 填寫：
      - 日期: 今天
      - 標題: "測試任務"
      - 描述: "這是一個測試描述"
   3. 點擊「創建提醒」
   4. 確認顯示：
      📝 測試任務
         這是一個測試描述
   ```

2. **測試排序**:
   ```
   1. 創建幾個任務（有些完成，有些未完成）
   2. 點擊排序按鈕
   3. 確認未完成的任務移到上方
   4. 再次點擊
   5. 確認按日期排序
   ```

3. **測試空狀態**:
   ```
   1. 切換到「過期」標籤
   2. 如果沒有任務，應顯示「無過期任務」
   3. 切換到「未來」標籤
   4. 如果沒有任務，應顯示「無未來任務」
   ```

## 🚨 注意事項

1. **資料庫遷移**: 
   - 新安裝的應用程式會自動使用新的資料庫結構
   - 已有資料的用戶需要刪除舊資料庫（或我們需要添加遷移邏輯）

2. **打包前確認**:
   - 確保 `prisma/dev.db` 包含最新的結構
   - 確保 `npx prisma generate` 已執行

3. **開發 vs 生產**:
   - 開發環境使用 `prisma/dev.db`
   - Electron 打包版本會複製這個資料庫作為模板
   - 用戶資料存儲在 `%APPDATA%\spreadsheet-comparator\dev.db`
