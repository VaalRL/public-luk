# 自動對帳功能實作總結

## 實作日期
2025-11-26

## 功能概述
根據初始需求.md，實作了智慧自動對帳功能，能夠自動匹配銀行交易與未結帳單。

## 核心邏輯

### 1. 對帳流程
1. **提取後五碼**：從銀行交易摘要中提取匯款帳號後五碼
2. **分組匯總**：將相同後五碼的交易分組，計算總進帳金額
3. **識別公司**：根據後五碼查找對應的公司
4. **共用帳號處理**：
   - 如果後五碼只對應一家公司 → 自動對帳
   - 如果後五碼對應多家公司 → 標記為「需人工審核」
5. **FIFO 沖銷**：按帳單日期由舊到新進行沖銷

### 2. 共用帳號處理（重要變更）
當檢測到一個匯款帳號被多個公司使用時：
- ❌ **不會**自動合併這些公司進行對帳
- ⚠️ 將這些交易標記為 `status: "ambiguous"`
- 🔍 在 UI 中以橙色警告卡片顯示
- 👤 需要使用者手動確認歸屬後處理

### 3. 交易狀態
- `unmatched`: 未對帳（初始狀態）
- `matched`: 已對帳
- `ambiguous`: 需人工審核（共用帳號）

## 使用流程

### 對帳頁面操作
1. 進入「對帳管理」頁面
2. 上傳銀行明細（CSV/Excel）
3. 點擊「執行自動對帳」按鈕
4. 系統自動處理：
   - ✅ 自動匹配單一公司的交易
   - ⚠️ 標記共用帳號的交易
   - ❓ 標記不明來源的交易
5. 查看對帳結果：
   - 已對帳交易顯示綠色「已對帳」標籤
   - 需人工審核的交易顯示在橙色警告區塊
   - 未結帳單列表更新已付金額

### 人工審核流程
對於標記為「需人工審核」的交易：
1. 查看橙色警告卡片中的交易明細
2. 根據實際情況確認該交易屬於哪家公司
3. 手動建立對帳記錄（未來可新增手動對帳功能）

## 測試情境

### 情境 1：單一公司單一帳號
- 公司 A：帳號 `12345`
- 交易：`ATM轉帳 12345` $10,000
- 結果：✅ 自動對帳成功

### 情境 2：單一公司多個帳號
- 公司 A：帳號 `12345`, `67890`
- 交易：`12345` $5,000 + `67890` $3,000
- 結果：✅ 合併處理，總進帳 $8,000

### 情境 3：共用帳號（需人工審核）
- 公司 A：帳號 `12345`, `88888`
- 公司 B：帳號 `67890`, `88888`
- 交易：`共用帳號 88888` $15,000
- 結果：⚠️ 標記為需人工審核

### 情境 4：不明來源
- 交易：`未知來源 11111` $5,000
- 沒有公司使用 `11111`
- 結果：❓ 標記為不明來源

## 技術細節

### 演算法複雜度
- 時間複雜度：O(n + m)，n 為交易數，m 為帳單數
- 空間複雜度：O(n + m)

### 資料庫操作
- 使用 Prisma ORM
- 交易式操作確保資料一致性
- 自動更新帳單狀態（unpaid → partial → paid）

### 錯誤處理
- 無法識別的交易：記錄在 `unidentifiableTransactions`
- 未知帳號：記錄在 `unknownAccounts`
- 共用帳號：記錄在 `ambiguousTransactions`
