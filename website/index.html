為什麼做這個

小公司的對帳，卡在同一個地方

收款用虛擬帳號，銀行明細上只留下後五碼。客戶不會告訴你這筆錢付的是哪一張單。

只有後五碼可以認人
明細摘要是「ATM轉入 12345」，要先查出這組後五碼屬於哪家公司，才知道這筆錢是誰付的。
一筆錢可能付好幾張單
客戶常常一次匯一筆整數，要自己拆開沖銷多張未結帳單，還得記得剩下的餘額。
金額對不上就要翻舊帳
多收的錢要留到下個月，少收的要追。這些狀態散在 Excel 和記憶裡，換人接手就斷了。

運作方式

三個步驟，從明細到結清

上傳銀行明細

直接丟銀行匯出的 Excel。第一次使用時用對應畫面指定哪一欄是日期、金額、摘要，之後存成模板重複套用。

自動歸戶與沖銷

從摘要抽出後五碼認出客戶，再依帳單日期先進先出沖銷。多收的錢自動轉為該客戶的溢繳額度，下期可直接扣抵。

月結留痕，不刪憑證

月結只把該期交易標記為已結，不刪除任何憑證。事後要追「這筆錢當初怎麼認的」，記錄都還在。

使用前提

先說清楚它不是什麼

這是一個小公司內部用的單機工具，不是 SaaS。裝之前請確認這些條件你能接受。

無帳號
沒有登入機制

任何能連到這個服務的人都能看到全部帳務，也能刪除資料。請只在自己的電腦上執行，不要放到公開網路。

單機
資料存在本機的 SQLite

沒有雲端同步，也沒有多人協作。換電腦要自己搬檔案，請自行安排定期備份。

台灣
針對台灣的收款習慣設計

對帳邏輯建立在「虛擬帳號後五碼」這個前提上，幣別與稅率預設為新台幣與 5% 營業稅。

開始使用

從原始碼跑起來

# 取得原始碼
git clone https://github.com/VaalRL/public-luk
cd public-luk

# 安裝與建立資料庫
npm install
npx prisma migrate deploy

# 啟動，開 http://localhost:3001
npm run dev
  • 執行環境Node.js 20+
  • 資料庫SQLite（內建）
  • 桌面版打包electron-builder
  • 授權MIT

xlsx 相依套件指向 SheetJS 官方 CDN 而非 npm registry， 這是刻意的 —— registry 上的版本停在 2022 年且缺少後續的安全性修復。 若你的網路擋住該網域，請先設定 proxy。
