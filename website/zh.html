為什麼做這個

一筆應收帳款，斷在兩個地方

開單跟收款通常是兩套互不相干的習慣：一邊是 Word 檔，一邊是銀行明細，中間只靠某個人的記憶連著。

報價單每次重打一遍
複製上個月的檔案改數字、手動編單號、自己算 5% 稅、再匯出 PDF。每次十分鐘，而且打錯只差一個鍵。
單開出去就沒人追了
文件寄出去，應收帳款落在 Excel 裡 —— 前提是有人記得補上去。誰還欠多少、欠多久，工具答不出來。
收款只有後五碼可以認
明細摘要是「ATM轉入 12345」，要先查出這組後五碼屬於哪家公司；客戶又常常一次匯一筆整數，得自己拆開沖銷多張單，還要記得剩下的餘額。

運作方式

四個步驟，從報價單到結清

開報價單

選客戶、套用存好的常用品項，單號、5% 營業稅與各項合計自動算好。PDF 的版型 —— 欄位名稱、紙張大小、簽章欄、附註 —— 都可以在設定頁調成你公司的樣子，設定一次就好。

出單同時立帳

產生 PDF 的同時就記下這筆錢是誰欠的、從哪一天起算。每份文件自動歸檔備份，也可以掛上提醒，之後要催款有依據。

上傳銀行明細

直接丟銀行匯出的 Excel。第一次使用時用對應畫面指定哪一欄是日期、金額、摘要，之後存成模板重複套用。

自動沖銷，月結留痕

從摘要抽出後五碼認出客戶，再依帳單日期先進先出沖銷；多收的錢自動轉為該客戶的溢繳額度，下期直接扣抵。月結只把該期交易標記為已結，不刪除任何憑證，事後要追「這筆錢當初怎麼認的」記錄都還在。

原理

錢怎麼被分配到每一張單

以下兩個例子的數字，是把情境丟進實際的對帳程式跑出來的結果，不是示意。

一筆錢付好幾張單 甲公司匯來 200,000，名下有三張未結帳單。系統依帳單日期由舊到新（先進先出）逐張沖銷。
06/20 入帳 200,000 · 摘要 ATM轉入 11111
帳單日期應收本次沖銷結果
A-00105/0284,00084,000結清
A-00205/1863,00063,000結清
A-00306/0491,00053,000部分
已分配200,000

最舊的先收。200,000 剛好用完，最新的 A-003 只收到一部分，還欠 38,000 會留在未結清單裡繼續等。 如果匯進來的錢比全部應收還多，多的部分不會亂塞，而是轉成這家公司的溢繳額度，下期自動扣抵。

認不出是誰付的 乙公司與丙公司登記了相同的後五碼 22222，兩邊都剛好有一張 50,000 未結。這時候後五碼不足以判斷。
06/21 入帳 50,000 · 摘要 ATM轉入 22222
候選公司帳單應收本次沖銷結果
乙公司B-00150,0000未動
丙公司C-00150,0000未動
已分配0待確認

不確定就不猜。這筆入帳會被標記為「待確認」，兩家公司的帳都不動，交給你判斷。 寧可留一筆待辦，也不要讓錯的公司被記成已付款 —— 帳一旦記錯，追回來的成本遠高於當下多看一眼。

使用前提

先說清楚它不是什麼

這是一個小公司內部用的單機工具，不是 SaaS。裝之前請確認這些條件你能接受。

無帳號
沒有登入機制

任何能連到這個服務的人都能看到全部帳務，也能刪除資料。請只在自己的電腦上執行，不要放到公開網路。

單機
資料存在本機的 SQLite

沒有雲端同步，也沒有多人協作。換電腦要自己搬檔案，請自行安排定期備份。

台灣
針對台灣的習慣設計

對帳邏輯建立在「虛擬帳號後五碼」這個前提上，報價單預設新台幣與 5% 營業稅。介面可切換中文或英文，但產生的文件是照台灣的使用習慣排版。

開始使用

從原始碼跑起來

# 取得原始碼
git clone https://github.com/VaalRL/public-luk
cd public-luk

# 安裝與建立資料庫
npm install
npx prisma migrate deploy

# 啟動，開 http://localhost:3001
npm run dev
  • 執行環境Node.js 20+
  • 資料庫SQLite（內建）
  • 桌面版打包electron-builder
  • 授權MIT

xlsx 相依套件指向 SheetJS 官方 CDN 而非 npm registry， 這是刻意的 —— registry 上的版本停在 2022 年且缺少後續的安全性修復。 若你的網路擋住該網域，請先設定 proxy。
